1. Project Overview

BankInsight AI is an end-to-end data analytics, machine learning, and AI-assisted decision platform built on the UCI Bank Marketing dataset (41,172 cleaned client records from 2008–2013). It integrates automated data profiling, cleaning, an analytical SQLite engine with 12 SQL query modules, target-leakage-free machine learning pipelines, explainable AI feature importances, a context-grounded LLM Q&A engine with zero-hallucination rule-based fallback, and a production-ready interactive web dashboard.

The platform empowers financial marketing managers to optimise direct telemarketing campaigns for term deposit subscriptions by identifying high-conversion customer profiles, predicting subscription propensity, and providing AI-driven conversational insights grounded exclusively in validated analytical findings.

2. Problem Statement

Direct telemarketing campaigns incur high operational call costs, with a low baseline conversion rate of only 11.27% and a severe class imbalance of 7.9:1 (non-subscribers per subscriber). Calling all clients indiscriminately wastes resources and alienates leads through persistent over-contacting.

Furthermore, naive machine learning approaches suffer from target leakage by including call duration — a variable that is unknown prior to making a call and is therefore unavailable at prediction time. BankInsight AI addresses these challenges by identifying high-conversion customer segments, enforcing target leakage prevention, delivering predictive lead-scoring models, and providing AI-driven decision support.

3. Objectives

  1. Automated Profiling & Quality Audit — Inspect 21 raw columns, generate schema dictionaries, and assess data quality.
  2. Data Cleaning — Remove duplicate records, drop non-contact noise (duration = 0), and standardise categorical values.
  3. Exploratory Data Analysis (EDA) — Identify demographic, campaign, and macro-economic conversion drivers through 10 analytical visualisations.
  4. SQL Analytics Engine — Build a relational SQLite database (bankinsight.db) and run 12 validated SQL analytics queries.
  5. Leakage-Free Feature Engineering — Exclude duration and collinear macro indicators; engineer 16 new features from domain knowledge.
  6. Supervised ML Classification — Train and compare Baseline, Logistic Regression, and Random Forest models with stratified cross-validation.
  7. Explainable AI (XAI) — Quantify top predictive features influencing customer subscription decisions.
  8. Grounded AI Q&A Engine — Provide natural-language answers backed strictly by validated analytical findings.
  9. Interactive Web Dashboard — Serve an executive web dashboard with dynamic charts and an embedded AI Chat Assistant.
  10. Testing & Validation — Automated test suite covering data, SQL, ML, AI, dashboard, edge cases, and code quality.

5. Data Understanding & Profiling (Phase 1)

Phase 1 performs automated inspection of all 21 raw columns, generating a data dictionary, descriptive statistics, target distribution analysis, and a data quality summary report.

Key Profiling Findings

  • Zero null values in any column — "missing" data is encoded as the string "unknown" in 6 categorical columns.
  • 12 exact duplicate row pairs identified (identical across all 21 columns).
  • 4 rows with duration == 0 (call never happened; all have y = no).
  • pdays sentinel: 96.3% of values are 999 (never previously contacted).
  • Target distribution: Severe imbalance — 88.73% "no" vs 11.27% "yes".

13. AI Query Engine & Fallback (Phase 8)

13.1 Architecture

  • phase8_ai_context.py — Builds a factual context string (~6,800 chars) from validated analytical outputs.
  • phase8_ai_engine.py — Wraps context + user question in a strict system prompt and calls OpenAI Chat Completions API (gpt-4o-mini).
  • Rule-Based Fallback — When no API key is set or the network is offline, the engine seamlessly switches to a pre-built rule-based response engine with 8 topic categories.

13.2 Zero-Hallucination Rules

  1. Only cite numbers that appear verbatim in the analytical context.
  2. If the context doesn't contain an answer, say so explicitly.
  3. Clearly label FACT (from context) vs INTERPRETATION (reasoning).
  4. Never reference features that don't exist in the dataset (e.g., 'balance').

All AI settings are loaded from .env (never hardcoded):

20. Limitations

  1. Duration Exclusion: duration is excluded to prevent target leakage, which limits maximum attainable F1-score to approximately 0.48 (without it, models can easily exceed 0.90 — but this is a false result).
  2. Class Imbalance: The severe 7.9:1 imbalance limits precision at the default 0.5 decision threshold. Cost-sensitive threshold tuning could improve practical deployment performance.
  3. No Financial Balance: The UCI Bank Marketing v2 dataset does not include client bank account balances, limiting client financial profile depth.
  4. Historical Data: The dataset covers 2008–2013 (post-financial-crisis period). Model performance may differ on contemporary data with different macro-economic conditions.

21. Future Scope

  1. Cost-Sensitive Threshold Optimisation — Optimise classification decision threshold based on specific call-centre costs vs term deposit revenue.
  2. Gradient Boosting Models — Integrate LightGBM and XGBoost for incremental accuracy gains.
  3. SHAP Values — Add SHAP (SHapley Additive exPlanations) for instance-level explainability.
  4. CRM API Integrations — Build webhooks for direct lead push to CRM systems (Salesforce, HubSpot).
  5. Real-Time Scoring API — Deploy model as a REST endpoint for live lead-scoring in production.
